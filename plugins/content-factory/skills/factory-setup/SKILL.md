# Установка контент-фабрики

Ты ставишь контент-фабрику человеку, который **не программист**. Он пришёл на интенсив, чтобы делать контент, а не разбираться в терминале.

## Как себя вести

- Объясняй каждый шаг **одной строкой человеческим языком**: что сейчас делаешь и зачем. Без слов «зависимости», «бинарник», «пайплайн».
- **Спрашивай разрешение перед установкой любой программы.** Скажи, что ставишь и сколько это займёт.
- Дошёл до ошибки — не молчи и не выдумывай. Покажи, что именно не вышло, и предложи следующий шаг.
- В конце **обязательно** покажи готовый смонтированный ролик. Установка засчитана только так.
- Никогда не проси прислать ключи в чат. Ключи человек вписывает сам в файл `.env`.

## Шаг 0. Убедись, что ты в правильной папке

Это первое, что нужно сделать, и до этого **ничего не скачивай**.

Покажи человеку полный путь текущей папки и спроси, та ли это папка, которую он создал
под фабрику (обычно `C:\Claude\content-factory` или `~/Claude/content-factory`).

Три признака, что открыто **не то** — при любом из них остановись и объясни:

- путь не совпадает с тем, что назвал человек;
- папка не пустая: внутри уже лежит чужой проект, а не пара файлов;
- это чужой git-репозиторий с историей и незакоммиченными изменениями
  (`git rev-parse --show-toplevel` отвечает путём, `git status` показывает сотни файлов,
  в интерфейсе видна кнопка Create PR и счётчик изменений).

Последний случай — самый частый и самый неприятный: человек открыл в Code рабочее
пространство другого проекта, и фабрика уедет внутрь него. Скажи прямо: «сейчас открыт
проект X, а нужна ваша пустая папка Y» и объясни, как переключиться — **Code → Local →
Select folder**, выбрать нужную папку, а не «открыть последнюю».

Дальше по всему тексту «рабочая папка» — это та самая папка человека. Движок ляжет
в её подпапку `factory`, а `CLAUDE.md`, `.claude/skills/` и `.mcp.json` — рядом с ней,
не внутри `factory`. Так обновление движка не затирает настройки человека.

## Шаг 1. Что уже есть

Проверь и скажи человеку результат простым списком «есть / нет»:

- `node --version` — нужна 20 или новее
- `git --version`
- `ffmpeg -version` и `ffprobe -version`
- на Windows: `winget --version` · на macOS: `brew --version`

Ничего пока не ставь. Сначала покажи картину целиком.

## Шаг 2. Доставить, чего не хватает

Windows (PowerShell):

```powershell
winget install --id OpenJS.NodeJS.LTS --accept-source-agreements --accept-package-agreements
winget install --id Gyan.FFmpeg --accept-source-agreements --accept-package-agreements
winget install --id yt-dlp.yt-dlp --accept-source-agreements --accept-package-agreements
```

macOS:

```bash
brew install node ffmpeg yt-dlp
```

Важное про Windows: после установки `ffmpeg` текущее окно приложения может его не увидеть — это нормально, PATH обновляется при перезапуске. Скажи об этом человеку заранее, чтобы он не пугался. Фабрика умеет находить ffmpeg и мимо PATH, так что чаще всего перезапуск не понадобится.

Если на macOS Claude просит разрешение на сетевые домены — так и должно быть, это песочница. Пусть разрешает.

## Шаг 3. Забрать движок

Если комплект уже склонирован (ты читаешь этот файл из папки `factory`) — шаг клонирования пропусти и переходи к установке зависимостей.

```bash
git clone https://github.com/ikigai-promotion-kz/ikigai-content-factory.git factory
cd factory/engine
npm install
npx playwright install chromium
```

**Все дальнейшие команды выполняются из папки `factory/engine`.** Если сессия перезапустилась и текущая папка сбилась — сначала вернись в `factory/engine`, потом запускай.

Скажи, что `playwright` — это браузер, которым фабрика рисует титры и субтитры.

Предупреди заранее: он качается **не в папку проекта**, а в общий кэш системы
(на Windows — `AppData\Local\ms-playwright` в профиле пользователя, на macOS —
`~/Library/Caches/ms-playwright/`) и занимает там **около 700 МБ** — так
Playwright устроен, разные проекты берут один браузер, а не по копии каждый. Если у
человека мало места на системном диске, это надо знать до установки, а не после.

## Шаг 3а. Скиллы — чтобы фабрику можно было звать словами

Скопируй **все папки** из `factory/plugins/content-factory/skills/` в `.claude/skills/`
рабочей папки (не внутрь `factory`). Сейчас их четыре:

- `factory-setup` — установка и проверка (этот файл);
- `reels-montage` — монтаж вертикального видео;
- `carousel-factory` — карусели, слайды и баннеры;
- `content-set` — выпуск целиком: одна тема → карусель, Reels, сторис и баннер в одном стиле.

Скопировал — скажи человеку, что теперь можно просто писать словами: «смонтируй Reels
из этого видео», «сделай карусель про <тему>» или «собери выпуск про <тему>», и нужный
скилл подхватится сам.

Считай папки по факту, а не по этому списку: комплект пополняется, и число здесь может
отстать. Скопируй столько, сколько нашёл, и назови человеку их имена. Если папок меньше
четырёх — не гадай, покажи список того, что есть: значит движок скачался не полностью.

## Шаг 4. Ключи

Скопируй `factory/engine/.env.example` в `factory/engine/.env` (Windows: `copy`, macOS: `cp`) и объясни человеку, что вписать. **Сам ключи не запрашивай и не вставляй** — покажи строку и путь к файлу, человек вписывает сам:

- `OPENAI_API_KEY` — **необязательный**: платная расшифровка речи, чуть точнее. Без него всё работает — есть бесплатная локальная (`reels/transcribe-local.mjs`).
- `FAL_KEY` — генерация картинок. Нужен со второго дня.

Higgsfield ключом **не подключается**: в приложении Claude это `Customize → Connectors → https://mcp.higgsfield.ai/mcp`, вход через браузер. Если человек этого ещё не сделал — подскажи, но не блокируй установку.

**Для генерации картинок хватает `FAL_KEY` в `.env`** — движок ходит в fal напрямую,
никакие коннекторы для этого не нужны.

Отдельный файл `.mcp.json` нужен только для того, чтобы звать инструменты fal прямо из
чата. Он не обязателен, и **записать его тебе, скорее всего, не дадут**: приложение
блокирует изменение своих настроечных файлов агентом (проверено на живой установке
29.07.2026). Не бейся об это и не выдумывай обходные пути — покажи человеку содержимое
`factory/.mcp.json.example`, скажи, куда положить файл (корень рабочей папки, не внутрь
`factory`), и что создать его нужно самому. Отказался — ничего не сломалось.

## Шаг 4а. Правила проекта

**Сначала проверь, есть ли уже `CLAUDE.md` в корне рабочей папки.**

- **Файла нет** — скопируй туда `factory/CLAUDE.md.template`.
- **Файл есть** — НЕ перезаписывай и не дописывай молча. Это правила человека, они
  старше фабрики. Покажи, какие разделы шаблона ты предлагаешь добавить, и спроси
  разрешение. Отказался — ничего не меняй, фабрика работает и так.

Это файл, который Claude читает автоматически в каждой сессии: бренд, голос, стоп-слова,
правила работы с видео и деньгами.

Пройдись по нему вместе с человеком и заполни угловые скобки его словами — спрашивай по одному пункту, не вываливай всю анкету сразу. Не знает ответа — оставь плейсхолдер и скажи, что вернётесь к этому после домашнего задания.

## Шаг 5. Проверка

```bash
node reels/check-deps.mjs
```

Разбери вывод вместе с человеком: что зелёное, что нет. `СТОП` — возвращайся к шагу 2.

## Шаг 6. Первый ролик — это и есть приёмка

```bash
node reels/montage/run.mjs demo/demo.config.mjs
```

Прогон занимает 1–2 минуты: фабрика вырезает паузы, режет видео на планы, накладывает субтитры и титры. Кредиты не тратятся — всё считается на машине человека.

Когда файл готов — **открой его** (Windows: `start`, macOS: `open`) и скажи, что именно он видит: сколько было секунд, сколько стало, сколько получилось склеек. Затем предложи следующий шаг: смонтировать его собственное видео.

## Подключить маркет-исследование — без него фабрика пишет мимо

Самый важный файл во всей фабрике человек делает сам, один раз: `marketing-context.md`.
Это результат домашнего задания — глубокое исследование рынка руками AI, 18 разделов:
кто аудитория, **какими словами она сама описывает свою проблему**, за что платит,
что отвечать на возражения, какие углы и хуки работают.

Без него любая генерация — гладкий текст про выдуманные боли выдуманных людей.

### Куда положить

**Рядом с папкой `factory`, а не внутри неё:**

```
Claude/content-factory/
├── factory/                  ← движок, обновляется целиком
├── marketing-context.md      ← актив человека, обновление его не трогает
└── CLAUDE.md
```

Это важно: всё внутри `factory` при обновлении перезаписывается. Файл снаружи — переживёт
любое количество обновлений.

### Как принять файл

Когда человек говорит, что research готов:

1. **Найди файл.** Смотри по порядку: `./marketing-context.md`, `../marketing-context.md`,
   `./context/marketing-context.md`. Нашёл не там, где ждали, — скажи, куда переложить.
2. **Проверь, что это не пустышка.** Пройди по списку и назови человеку, что не сходится:
   - в разделе про аудиторию стоят **живые фразы людей**, а не причёсанный маркетинг;
   - персон **три и больше**, у каждой боль, триггер и возражения;
   - углов атаки **12 и больше**, и они разного типа, а не восемь вариаций одного;
   - хуков **40 и больше**, каждый читается как речь человека, а не слоган агентства;
   - есть **список источников**, и ссылки в нём рабочие — открой три наугад;
   - есть раздел «что подтверждено / что гипотеза / что проверить».

   **Самая быстрая проверка на халтуру:** если ссылки битые или ведут не туда — модель
   не искала, а сочиняла. Такой файл использовать нельзя, он отравит все генерации.
   Скажи это прямо и предложи перегенерировать конкретный раздел, а не весь файл.

3. **Пропиши в `CLAUDE.md`** строку, которая включает файл в работу:
   «Перед созданием любого рекламного текста, карусели или сценария читай
   `marketing-context.md` и опирайся на него: там аудитория, её собственные слова,
   возражения и углы атаки».
4. **Проверь, что нет запрещённого.** Если в исследовании есть цифры или имена клиентов,
   на которые нет прав или подтверждения — вынеси их в раздел «чего не писать» прямо
   в файле. Иначе фабрика будет повторять их в каждом посте. Это не паранойя: у нас
   самих в исследовании нашлась чужая цифра выпускников, поданная как своя.
5. **Скажи, что изменилось.** Одной строкой: теперь карусели и ролики пишутся под
   конкретную персону её словами, а не «для предпринимателей».

### Файла ещё нет

Не выдумывай его и не предлагай «набросать примерно». Скажи прямо: без исследования
фабрика будет писать общими словами, и дай ссылку на домашнее задание интенсива.
Работать можно и так — но результат будет ровно на том уровне, на каком человек
опишет свой продукт в `CLAUDE.md`.

## Регулярный выпуск: расписание внутри приложения Claude

Когда человек хочет «чтобы само выходило по расписанию» — у приложения Claude есть
локальные расписания (Routines). Ставится задача словами, например: «каждый вторник в 10:00
собери выпуск про <тему> по скиллу content-set и покажи мне план на согласование».

**Скажи честно, где предел** — это не сервер, а расписание на его компьютере:

- работает, **только пока приложение открыто** и компьютер не спит;
- закрыл ноутбук — запуск пропущен, задним числом не догонит;
- задача, которая тратит деньги, всё равно должна спрашивать разрешение: ставь в
  формулировку «покажи план и дождись моего да», а не «опубликуй».

Что имеет смысл ставить на расписание, а что нет:

| Годится | Не годится |
|---|---|
| собрать план выпуска к утру | публиковать без просмотра |
| напомнить, что пора снять дубль | генерировать пачку кадров ночью |
| пересобрать монтаж после правки конфига (бесплатно) | всё, где нужен взгляд человека на результат |

Правило простое: на расписание вешается подготовка, а решение остаётся за человеком.

## Своё видео

Нужны два файла: видео и расшифровка речи с таймкодами слов. Дальше конфиг по образцу `reels/montage/example.config.mjs` — там описано каждое поле: свой заголовок-хук, свои титры на нужных фразах, свой финальный кадр.

Если расшифровки нет — сними её бесплатно, ключ не нужен:

```bash
node reels/transcribe-local.mjs ./его-видео.mp4
```

Первый запуск скачает модель (490 МБ), дальше офлайн. Платный вариант (`reels/transcribe.mjs`, ~$0.006 за минуту) предлагай только по просьбе — он точнее на плохом звуке. Рядом появится `его-видео.words.json` — этот путь идёт в поле `wordsPath`.
