## Принцип: модель = параметр конфига, не хардкод
Каждая image-модель на fal работает по одному SDK-паттерну → замена модели = одна строка в `config/models.json`, без переписывания воркера. Для production — **submit + webhook** (не subscribe — он держит соединение и убивает параллелизм).

## Рекомендованный конфиг Creative Engine
```json
{
  "image": {
    "draft":  "fal-ai/qwen-image",
    "final":  "fal-ai/nano-banana-pro",
    "typo":   "fal-ai/flux-2-flex",
    "design": "fal-ai/recraft/v4/pro/text-to-image",
    "bulk":   "fal-ai/bytedance/seedream/v4/text-to-image",
    "edit":   "fal-ai/flux-pro/kontext",
    "brand":  "fal-ai/flux-lora-fast-training"
  }
}
```
Схема draft→final: черновики на Turbo (разведать промпт, 4-6 вариантов) → полное разрешение только на отобранных кадрах. На 1000 изобр/мес при 4:1 итерациях: FLUX.2-dev-turbo ~$32 vs Nano Banana Pro ~$600.

## 3 предупреждения по реализации
1. **Префикс `fal-ai/` есть не у всех** — ByteDance/Alibaba идут от имени лаборатории (`bytedance/seedance-2.0/...`, `alibaba/...`). Автосклейка `"fal-ai/" + model` сломается на них.
2. **Названия карточек ≠ slug** — «Kling 3.0 Pro» в доках может вести на `v2.5-turbo`. Ориентир — slug, не подпись.
3. **Источник истины — `https://fal.ai/docs/llms.txt`**, не этот файл. Каталог меняется быстрее любого списка.
