## Принцип: модель = параметр конфига, не хардкод
Каждая image-модель на fal работает по одному SDK-паттерну → замена модели = одна строка в `config/models.json`, без переписывания воркера. Для production — **submit + webhook** (не subscribe — он держит соединение и убивает параллелизм).

## Рекомендованный конфиг Creative Engine
```json
{
  "image": {
    "draft":  "fal-ai/qwen-image",
    "final":  "fal-ai/nano-banana-pro",
    "typo":   "fal-ai/flux-2-flex",
    "design": "fal-ai/recraft/v4/pro/text-to-image",
    "bulk":   "fal-ai/bytedance/seedream/v4/text-to-image",
    "edit":   "fal-ai/flux-pro/kontext",
    "brand":  "fal-ai/flux-lora-fast-training"
  }
}
```
Схема draft→final: черновики на Turbo (разведать промпт, 4-6 вариантов) → полное разрешение только на отобранных кадрах. На 1000 изобр/мес при 4:1 итерациях: FLUX.2-dev-turbo ~$32 vs Nano Banana Pro ~$600.

## 3 предупреждения по реализации
1. **Префикс `fal-ai/` есть не у всех** — ByteDance/Alibaba идут от имени лаборатории (`bytedance/seedance-2.0/...`, `alibaba/...`). Автосклейка `"fal-ai/" + model` сломается на них.
2. **Названия карточек ≠ slug** — «Kling 3.0 Pro» в доках может вести на `v2.5-turbo`. Ориентир — slug, не подпись.
3. **Источник истины — `https://fal.ai/docs/llms.txt`**, не этот файл. Каталог меняется быстрее любого списка.

## Higgsfield: новые модели изображений, сверено 09.09.2026

Новинки замечены в интерфейсе, состав сверен машинно через каталог коннектора
(`models_explore action=list type=image`) и через `higgsfield model get <id>` — не по скриншоту.

### `gpt_image_2_5` — GPT Image 2.5 (OpenAI)

| Параметр | Значения | По умолчанию |
|---|---|---|
| `variant` | `flare` (быстрые повседневные кадры) · `sunburst` (максимальное качество, точные правки) | `flare` |
| `quality` | low · medium · high · **xhigh** · **max** | `low` |
| `resolution` | 1k · 2k · 4k | `1k` |
| `background` | auto · opaque · **transparent** | — |
| `aspect_ratio` | auto, 1:1, 3:2, 2:3, 4:3, 3:4, 16:9, 9:16, 21:9, **27:16, 16:27, 9:8, 8:9** | 1:1 |
| медиа | роль `image_references` | — |

**Что здесь нового против `gpt_image_2`:**
1. **`xhigh` и `max`** — два уровня качества выше потолка GPT Image 2 (`high`).
2. **`background: transparent`** — прозрачный фон прямо из модели. Раньше вырезанные объекты
   и персонажей мы получали постобработкой.
3. Новые соотношения сторон 27:16, 16:27, 9:8, 8:9.
4. ⚠️ Роль медиа называется `image_references`, у `gpt_image_2` — `image`. При переносе
   промптов это ловушка.
5. ⚠️ Безлимитных генераций **не поддерживает** (`gpt_image_2` поддерживает).

**Замер на боевой задаче (обложка YouTube, 09.09.2026).** Один и тот же промпт
(«Warm Editorial Glow», плакат с крупной кириллицей) прогнан на `gpt_image_2` (2k/high) и на
`gpt_image_2_5` (variant `sunburst`, quality `xhigh`, 2k):

- **Кириллица — одинаково чистая у обеих**, ни одной ошибки в обеих.
- **Стиль держит лучше `gpt_image_2`**: он собрал именно плакат — слоистые бумажные карточки,
  флэт-заливки, зерно.
- **`gpt_image_2_5/sunburst` ушёл в фотореализм**: настоящий стол, кружка, книги, растения,
  мягкий свет. Картинка красивее как фотография, но это фотосток, а не плакат кампании.

**Правило по итогу замера:** для плакатной типографики и флэт-стиля остаётся `gpt_image_2`.
`gpt_image_2_5/sunburst` брать, когда нужна **фотореалистичная сцена с безупречным русским
текстом** — это его сильная сторона. И это единственная модель у нас с прозрачным фоном.

### GPT Image 2.5 — что заявила OpenAI (релиз 08.09.2026, дополнено 10.09.2026)

Модель вышла 08.09.2026 и за два дня стала главной темой у блогеров. Официально:
- **`flare`** — вариант по умолчанию, задержка до −50 % против Images 2.0; **`sunburst`** —
  премиум для кампаний и предметки, точнее держит правки, работает дольше.
- Правит **только указанное**, остальное оставляет на месте, даже на сложном фоне;
  стабильнее в многоходовой правке.
- **Лучше держит человека или персонажа с референс-фото** — одно лицо в разных сценах.
- Сложные раскладки, прозрачный фон, точнее реальные объекты, ровнее держит заданный стиль.
- Шаблоны постеров и мерча; уровни качества low · medium · high · xhigh · max; цена токенов
  в API как у `gpt-image-2`.
- ⚠️ **Выделение области («сделай зелёным») и `@Sketch` есть только в интерфейсе ChatGPT.**
  У CLI Higgsfield параметра маски нет: правка идёт текстом + `--image-references`.

**Цена в Higgsfield (замер `generate cost`, 10.09.2026):** `flare/high/2k` — 5,5 кр. ·
`sunburst/xhigh/2k` — 8 кр. за кадр.

**Референс персонажа ДОХОДИТ (проверка 10.09.2026).** Лист персонажа передан через
`--image-references <путь>`: в `params.medias` задания лежит загруженная картинка (роль `image`),
кадр совпал с листом по лицу, причёске, одежде и осанке. У `gpt_image_2` в такой же серии поле
`medias` пустое — там персонаж держится только на тексте промпта. **Значит, серии с персонажем,
где нужна кириллица, переводим на `gpt_image_2_5` с листом персонажа в референсе.**
Промпт при этом описывает сцену, а не лист: текст листа модель выполнит буквально и снова
нарисует лист.

**Правило выбора (уточнено 10.09.2026):**
- флэт-плакат, коллаж, бумажные карточки → `gpt_image_2`;
- фотореалистичная редакционная съёмка, один герой через всю серию, крупная кириллица →
  `gpt_image_2_5/sunburst` (стиль «Фэшн-редакционный плакат», разбор REF-12 в
  `reference/_ANALYSIS.md`);
- персонаж (маскот) в сцене с текстом → `gpt_image_2_5` + лист персонажа в `--image-references`.

### Грабли CLI Higgsfield (поймано 09.09.2026)

**Многострочный промпт через `--prompt "$(cat file.txt)"` доезжает только первой строкой.**
Остальные строки CLI разбирает как отдельные аргументы, из-за чего молча теряются и сам текст,
и все флаги после него: задание ушло с `aspect_ratio: 1:1` вместо 16:9 и вообще без референса,
хотя команда отработала с кодом 0. Признак — в `generate get <id>` поле `prompt` обрывается на
первой строке. **Промпт передавать одной строкой:** `P=$(tr '\n' ' ' < file.txt)`.
