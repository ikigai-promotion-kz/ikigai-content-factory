# Справочник видео-ремесла

> **Что это.** Словарь ремесла движущегося изображения: движение и easing, монтаж и ритм, свет и цвет, звук, платформенные механики соцсетей, парк AI-видео-моделей, психология внимания и триггеры распространения. Чек-листы и промпт-скелеты, а не теория ради теории.
>
> **Как читать.** Модули пронумерованы M01–M12. Монтажный слой фабрики опирается прежде всего на **M02 (монтаж и ритм)** и **M04 (звук)** — если читать выборочно, начните с них.
>
> **Про текст в кадре.** Слабые видео-модели рендерят кириллицу кракозябрами. Поэтому критичный текст всегда кладётся **слоем поверх видео**, а не «запекается» в генерацию. Именно так работает монтажный слой этого комплекта.
>
> ⚠️ Числа, помеченные **⚠ single-source**, взяты из одного источника или вторичных агрегаторов. Перед клиентскими материалами верифицируйте первоисточником; в презентациях говорите «по данным индустриальных обзоров», а не как о факте.

## Принципы движения (M01)

Базовая «операционная система» любого движущегося креатива — **12 принципов Диснея** (Thomas & Johnston, 1981) и их продуктовая компактная версия **10 принципов motion-дизайна** (JR Canest). Для движка это не теория, а **QA-чек-лист** перед публикацией AI-видео/motion — встраивается рядом с формулой G-A-P-S-B.

### QA-чек-лист «12→10 принципов» (прогон любого движущегося креатива)
- **Squash & Stretch / Smears** — деформация при ускорении/ударе передаёт вес.
- **Anticipation** — микро-обратное движение перед основным действием.
- **Staging** — ясно, куда смотреть в первую очередь (один фокус).
- **Timing & Spacing (Eases)** — движение не линейное; ease-out для входа.
- **Arc** — траектория по дуге, не по прямой.
- **Follow Through / Overlapping** — вторичные элементы двигаются со сдвигом по времени, не синхронно с главным.
- **Secondary / Layered Action** — базовое движение усилено вторым смысловым слоем.
- **Exaggeration** — усиление контраста для абстрактных объектов (иконки, геометрия).
- **Appeal** — приятно смотреть даже без звука (автоплей в лентах беззвучный).

### Семантическая матрица easing (не декор, а смысл)
Линейное движение противоестественно (GSAP: easing — «самая важная часть motion-дизайна»). Кривая = сообщение:

| Easing | Смысл | Где применять |
|---|---|---|
| **ease-out** | мяч катится до остановки → отзывчивость + трение | **вход/появление** элемента в UI и карусели (дефолт) |
| **ease-in** | тяжёлый объект набирает скорость | **уход/исчезновение** из кадра |
| **ease-in-out** | разгон + торможение | **сложный переход** между состояниями |
| **back** | лёгкий перелёт с возвратом | **акцентный вход** текста/CTA |
| **bounce / elastic** | игривость | лого-стингер, спортивный/детский бренд |

Заменяет чисто технические CSS-переходы `motion.css` на семантику: не «какая красивая кривая», а «какую задачу внимания решает».

### Кинетическая типографика (текстовые слои Reels/анимированных каруселей)
- Хук-слово **в движении с 1-го кадра** — средняя длительность внимания в соцконтенте ~1.7 сек ⚠ single-source (верифицировать перед клиентскими материалами).
- Текст **читаем ≥0.5 сек** после «оседания» анимации.
- **Иерархия по интенсивности анимации** — главный месседж получает самую смелую анимацию, вторичное — сдержанную.
- Геометрический sans-serif (не тонкие скрипты — «плывут» при компрессии платформы).
- Обязательный **reduced-motion / статичный fallback**.

### Правила слайд/motion-анимации (Tomorrow's VA)
**Be Consistent** (один тип входа на всю колоду) · **Be Sensible** (анимировать только смысловое) · **Be Quick** (**0.5–3 сек макс**) · **Be Smooth** (плавный старт/финиш = slow in/out) · **Be Adaptive** (учитывать платформу/устройство).

### QA-гейт перед рендером
- [ ] Движение не линейное — easing-семантика соблюдена (ease-out=вход, ease-in-out=переход, back/bounce=акцент).
- [ ] Элементы появляются **layered** (со сдвигом), не всё синхронно.
- [ ] Один фокус (staging), приятно без звука (appeal).
- [ ] Длительность 0.5–3 сек, есть reduced-motion/static fallback.
- [ ] Скорость UI-перехода 100–500 мс ⚠ single-source (ориентир, верифицировать).

## Монтаж и ритм (M02)

Монтажная грамматика — конечный набор приёмов, у каждого своя драматургическая функция. Это язык для оценки смонтированного/AI-сгенерированного видео — QA-гейт рядом с G-A-P-S-B.

### Грамматика склеек
| Кат | Функция | Когда |
|---|---|---|
| **Hard/basic cut** | нейтральная смена | основа shot-reverse-shot |
| **J-cut** | звук след. сцены заходит **до** картинки | плавный вход в новую тему/локацию |
| **L-cut** | звук текущей сцены **тянется** на новую картинку | продлевает эмоцию |
| **Match cut** | визуальная/символическая рифма кадров | «умный» переход, брендовые истории |
| **Jump cut** | намеренный разрыв континуити | энергия/лапс времени (в TikTok — норма, не ошибка) |
| **Cut-in / insert** | деталь внутри того же кадра | акцент на объекте |
| **Cutaway** | переключение на другой план | маскирует ошибки, сбрасывает 180°-линию |

### Continuity (делает монтаж «невидимым»)
- **180°-правило** — камера по одну сторону оси между персонажами (сохраняет право/лево).
- **Eyeline match** — направление взгляда в кадре А совпадает с тем, куда смотрят в Б.
- **Правило 30°** — смена ракурса одного объекта минимум на 30°, иначе читается как случайный jump cut.
- **Match-on-action** — резать точно в момент движения.
- Пересечение 180°-линии — только через нейтральный кадр / движение камеры / cutaway.
- Частая ошибка — **rhythm mismatch**: темп склеек не совпадает с эмоциональным тоном (статичный план в динамичном экшне).

### Структура Hook → Body → Payoff (шаблон коротких видео)
- **Hook (1–3 сек)** — обязан остановить скролл **до первого слова**; open loop (curiosity gap), а не «представление».
- **Body (70–80% длительности)** — смена визуала каждые **3–5 сек**; реплика без визуальной смены — не дольше 8 сек; bridge-фраза между хуком и телом.
- **Payoff** — **конкретный, специфичный**, отрабатывает обещание хука; финал резкий (cut immediately) + быстрый CTA (≤2 сек) или loop-setup — не размытый.

### Retention-редактура (перед публикацией)
- [ ] Хук создаёт **open loop**, не просто «интро».
- [ ] Смена стимула каждые **3–6 сек** (новый визуал/план/акцент).
- [ ] **Punch-in** зумы **10–15%** на смысловом акценте.
- [ ] **Cut ruthlessly** — вырезано всё, что не даёт ценность / не двигает к пэйоффу / не держит любопытство.
- [ ] Многослойный звук поддерживает картинку, не дублирует.

### Протокол монтажа под бит
1. **Разметить трек ДО нарезки** (биты, дропы, паузы, BPM, куплет/хук/дроп).
2. Основные каты — на **downbeats** (сильные доли), **НЕ на каждый бит** (это любительская ошибка, ощущается лихорадочно).
3. Строить дугу: setup → acceleration → release → pause → reveal → payoff.
4. Продвинутое: **anticipation cuts** — кат на 1–2 кадра **раньше** бита субъективно точнее в такт.

### Платформенная дифференциация (один сюжет — разный монтаж)
**TikTok** — быстрый темп, джамп-каты, много текст-оверлеев, тренд-звук, AI-фильтры (энергия/веселье). **Reels** — плавные эстетичные переходы, slow-motion, минимум текста, упор на визуал. ⚠ single-source по сравнению темпов (верифицировать). CapCut 2026: AI one-click templates, beat sync, cinematic edits, speed ramping — ориентир для быстрой сборки вертикали.

## Свет и цвет в видео (M03)

### Correction ≠ Grading
**Коррекция** выравнивает экспозицию/баланс белого/контраст до реалистичного состояния. **Грейдинг** стилизует палитру ради настроения — идёт **строго после** коррекции. **LUT** — не «магический фильтр», а математическая таблица преобразования: 1D LUT = одна гамма-кривая (грубо), 3D LUT (`.cube`) маппит hue/sat/brightness по трём осям (реальный контроль). LUT не работает на несбалансированном сыром материале.

### Порядок операций (QA-гейт перед деливери — любой источник, съёмка или AI)
- [ ] **Picture profile** — Log или Log-подобное пространство (максимальный динамический диапазон).
- [ ] **Primary correction** — экспозиция/ББ/контраст выровнены по всему кадру и между шотами.
- [ ] **Neutralizing & matching** — все шоты сцены сведены к единой нейтральной базе до творчества.
- [ ] **Secondary correction** — точечно (кожа, объект) через маски.
- [ ] **Creative grade / LUT** — отдельным слоем поверх, не встроен в трансформацию цветового пространства.
- [ ] Стресс-тест: грейд проверен в Rec.709 SDR + вертикальном social-мастере.

### Схема света key / fill / rim
- **Key** — направление и характер сцены.
- **Fill** — заполняет тени key, управляет контрастом через **fill ratio** (слабее fill = драматичнее).
- **Rim (backlight)** — отделяет объект от фона, даёт глубину.

### High-key / low-key как режиссура внимания (не эстетика)
| High-key (ровный свет, мало теней) | Low-key (глубокие тени, контраст) |
|---|---|
| открытость, лёгкость, «без барьеров» | тайна, драма, направленное внимание |
| реклама, обучение, лайфстайл, **решение/payoff** | сторителлинг-хуки, **проблема/hook**, драматичные цифры |

**Связь с G-A-P-S-B:** hook в **low-key** (драма/проблема) → payoff в **high-key** (решение/лёгкость) — осознанный приём режиссуры вниманием через свет. Режим консистентен по всему ролику, не случайный по сценам.

### Teal & Orange (чек-лист брендового грейда)
Работает потому, что кожа физически в оранжевом спектре и выделяется на бирюзовом фоне (сепарейшн переднего плана).
- [ ] Тени/midtones → холодный полюс, света/кожа → тёплый.
- [ ] Комплементарная пара подобрана под фирменные цвета IKIGAI PROMOTION, не скопирована вслепую.
- [ ] Стоп-кадр без звука: «глаз сразу находит героя?»
- [ ] Не более одной доминирующей цветовой идеи на ролик.
- ⚠ «hue поднимает узнаваемость до 80%» — single-source (ориентир, верифицировать).

### Консистентность AI-кадров сцены — ГЛАВНЫЙ риск AI-видео сейчас
Плавающие лицо/дождь/город от кадра к кадру. Решение 2026:
- [ ] **Global style prompt** задан один раз для сцены и повторяется в каждом шот-промпте.
- [ ] **Character locking** — один и тот же референс-asset персонажа во всех кадрах.
- [ ] **Environment anchoring** — локация описана один раз, переиспользуется по референсу.
- [ ] **Explicit lighting spec в каждом промпте**: направление ключа, качество света, **цветовая температура в Kelvin**, fill/практические источники (вместо абстрактного «cinematic lighting» — **motivated lighting**: «тёплый свет от лампы за кадром слева»).
- [ ] **Reference frame extraction** — кадр из первого удачного шота как визуальный якорь для следующих.
- [ ] **Batch generation by location** — все шоты одной локации генерируются подряд + manual review на style drift.

## Звук (M04)

### 4 слоя строго по порядку (а не «Suno-трек поверх готового монтажа»)
1. **Диегетика** — то, что слышат персонажи (диалог, шаги, источник музыки в кадре) — заземление реальности.
2. **Ambient / атмосфера** — фоновая среда (гул города, шум помещения); **подложить ПЕРЕД музыкой**, иначе паузы между репликами звучат как «дыра».
3. **Недиегетика** — саундтрек, закадровый голос, стилизованные эффекты — эмоция для зрителя.
4. **Foley** — реконструированные бытовые звуки (шаги, шелест, удары), синхронные с действием — полировка физического присутствия (последний слой).

### Hit points — почему НЕ резать на каждый бит
**Hit point** — точный удар кадра/действия в музыкальный акцент. Плотная синхронизация («Mickey Mousing») уместна в анимации/комедии, дёшева в драме. Профессиональный ритм выбирает **опорные доли (downbeats)**; «кат на каждый бит» рвёт нарратив.

### Матрица SFX (разные задачи внимания, не взаимозаменяемы)
| Приём | Функция | Где |
|---|---|---|
| **Whoosh** | обозначить быстрое движение/переход | смена кадра/сцены, свайп |
| **Riser** | нарастание напряжения к кульминации | **перед** reveal/punchline/CTA |
| **Impact / Hit** | зафиксировать кульминацию | момент раскрытия оффера, «до/после», **ключевая цифра/панчлайн** |
| **Тишина / пауза** | сфокусировать внимание на следующем | **перед CTA**, перед хуком, после сильного заявления |

Звуковой эквивалент visual pattern interrupt для hook-bank (M06): riser перед оффером, impact на цифре, пауза перед CTA.

### Измеримый микс (QA-гейт)
- [ ] **Голос — приоритетный канал** (voice-priority; не разборчиво → нет целевого действия).
- [ ] Музыка под голосом тише на **~20–25 дБ** (кино-ориентир: музыка ≈ –20 дБ).
- [ ] **Сайдчейн-дакинг** музыки от голоса включён на всех участках с войсовером.
- [ ] Итоговая громкость **≈ –14 LUFS integrated**, **true peak ≤ –1 dBTP** (соц-бенчмарк, не жёсткая норма — единого стандарта TikTok/Reels нет).
- [ ] **«Тест на телефонном динамике»** и дешёвых наушниках — не только студийный мониторинг (баланс голос/музыка ломается именно на массовых устройствах ЦА).

### Оригинальное аудио vs тренд-звук
Звук на TikTok/Reels — **сигнал дистрибуции**, не украшение (алгоритм группирует видео по саунду). Тренд-звук даёт краткий буст на пике, но **оригинальное аудио** не имеет срока годности и даёт лучше brand recall. ⚠ Цифры «88% вовлечённости завязано на звук», рост охвата «×3–5» — single-source (вторичные SMM-агрегаторы; в презентациях — «индустриальный консенсус», не верифицированная TikTok-статистика). Решение native-vs-trending дифференцировать по платформе (см. M05).

## Платформенные механики 2026 (M05)

### «Идеальной длины нет»
Алгоритмы измеряют не длину, а **% досмотра и replays**: 15-сек ролик с 90% досмотра сильнее минутного с 35%. Ориентировочный sweet spot: TikTok 15–34 сек, Reels 15–60 сек, Shorts 30–90 сек — **диапазоны обзоров, не канон**. Хук в первые **2–3 сек** под TikTok Qualified Views.

### Safe-zone спеки ⚠ (цифры расходятся между версиями UI — верифицировать реальным превью в Creative Center)
| Платформа | Верх | Правый край (иконки) | Низ |
|---|---|---|---|
| **TikTok** (1080×1920) | ≈150–200 px | ≈120 px | ≈250–300 px |
| **Reels** (safe 1010×1280) | ≈220 px | — | ≈420 px |
| **Shorts** | центр-полоса | свободный правый край | нижняя зона под подпись |

- [ ] Ключевой текст/лого — в центральной полосе, вне зон UI.
- [ ] Правый край свободен (там лайк/коммент/шер).
- [ ] Рекламные плейсменты — текст ≈15% выше нижнего края, тест в Ads Manager.
- [ ] Шрифт medium/bold, line-height ≈1,3×, высокий контраст (тонкие «плывут» при компрессии).

### Loop-приёмы (повышают average view duration + replay rate)
- [ ] Закрывающая фраза/кадр **дословно продолжает** открывающую — склейка внутрь цикла незаметна.
- [ ] Обрезка на 1 кадр раньше/позже или кросс-фейд 2–4 кадра на стыке.
- [ ] Единая цветокоррекция начала/конца против «мерцания».
- Структурировать под loop **с самого сценария**, а не домонтировать петлю постфактум.

### Жизненный цикл тренд-звука
**Emerging** (дни 1–3, до 10k видео, максимальный буст) → **Growing** (дни 3–7, 10k–100k) → Peaking (7–14, 100k–500k) → **Declining** (3+ недели, минимальный буст). **Окно публикации 48–72 часа** от начала роста. Маркеры в Creative Center: «Breakout»/«New to Top 100» с <5000 видео.

### Метрики-сигналы
- **«200-view jail»** (TikTok) — видео застревает на ~200 просмотрах при нехватке **Qualified Views** (просмотры **длиннее 5 сек**) / низком completion rate.
- **Shares/sends (личная пересылка) — топ-сигнал ранжирования 2026** на IG (официально) и TikTok, обошли лайки. Закладывать **DM-шер-триггер** («отправь другу, кто…») в финал ролика.
- Photo Mode TikTok — метрика **Swipe-Through Rate**; «Search Value» (авто-субтитры + оверлеи ↔ поисковые запросы) — прямой фактор ранжирования.

## Роутер видео-моделей (M10)

Наш стек (**Kling / Veo / Sora / Seedance / Higgsfield**) закрывает объём, реализм, native-audio. Системный пробел — **директорский контроль на уровне кадра**. Рынок 2026: «нет одной лучшей модели» — держим мультимодельный роутинг (параллель с целью `/carousel-day` ШАГ 2.5).

### 6-слойная структура видео-промпта
```
[движение камеры] через/по [environment],
[subject] выполняет [action with motion],
[environmental motion details] (тени сдвигаются, туман поднимается),
[lighting с temporal quality + Kelvin],
[аудио-подсказка],
[style + technical specs]
negative: [3–5 терминов]
```
Без явного движения камеры и субъекта модель даёт «анимированную фотографию».

### Словарь движения камеры
`dolly` (наезд/отъезд по рельсу) · `pan` (поворот по горизонтали) · `tilt` (по вертикали) · `orbit` (облёт вокруг) · `push-in` (медленный наезд) · `crane` · `zoom` · `handheld` (живая тряска). **Движение субъекта описывать отдельно от движения камеры.**

### Negative prompts
**3–5 конкретных терминов** (`jittery motion, flickering, frame inconsistency, morphing, unnatural movement`). Свыше 5 — модель «over-constraining» вплоть до усиления исключаемых черт. Длина промпта 20–80 слов; свыше 100–150 — внимание фрагментируется.

### i2v vs t2v (чек-лист)
- [ ] Готовый продуктовый/брендовый ассет → **форсировать i2v** (быстрее, консистентность бренда, лучше для batch; данные: +65% engagement / +40% конверсии i2v vs статика в e-commerce).
- [ ] Сцена «с нуля» / абстрактная идея / явный контроль камеры-света по кадрам → **t2v** с полным мотивным словарём.

### Модель-специфика поверх 6-слойного промпта
- **Kling** — negative 3-5 терминов работает; multi-shot ⊥ Start/End при сквозном персонаже.
- **Veo** — структурировать аудио отдельными блоками `Dialogue:` / `SFX:` / `Ambient noise:`.
- **Seedance** — 1-2 субъекта максимум (мульти-субъект ломает анатомию), давать тайм-код-бит действий; reference держит идентичность.
- **MiniMax/Hailuo** — только одиночный субъект (мульти = «anatomy breakdown»).
- **Wan** — только с референсом (не чистый t2v).
- **Camera-preset** вместо слоя 1: у Cinema Studio/Higgsfield есть именованные `preset_id` движения камеры (`presets_show`) — брать пресет, а не свободный текст, когда нужен предсказуемый ход.
- ⚠ `negative_prompt` как API-поле есть НЕ у всех — проверять в MCP; где нет, нежелательное режь позитивным языком.

### Нативное аудио > TTS+lipsync
У `seedance_2_0`/`veo3_1`/`wan2_7`/`kling3_0`/`gemini_omni`/`grok_video` есть `generate_audio:true` / `sound:on` — **нативный синхронный звук дешевле и синхроннее**, чем отдельный TTS + липсинк. НО native ≠ гарантированно хороший: **критичный бренд-звук (джингл, конкретный RU-голос) — отдельно** через аудио-стек (`knowledge/neural-nets/higgsfield-audio-stack.md`: RU-эмоция → `text2speech_v2:elevenlabs`).

## Relight и постобработка (M11)

### «Одна съёмка → N настроений» через light transfer
Вместо полной перегенерации ролика под другое освещение — взять один готовый кадр и прогнать через relight с **референсом** (Light transfer переносит освещение с референс-изображения без ручной настройки). Дешевле по кредитам, чем re-prompt. Ключевое преимущество видео-relight — **консистентность освещения между кадрами без мерцания/сдвигающихся теней**. Ручной режим: интенсивность 2–4 даёт естественнее, чем экстремальные значения; вывод ограничен 1080p.

### Апскейл по задаче (нет единого лидера)
| Задача | Инструмент |
|---|---|
| «Изобретённая» деталь (мокапы, промо) | Magnific (Freepik) / Nano Banana Pro |
| Batch реальных фото/архива без галлюцинаций | Topaz Photo/Video AI |
| Максимальное разрешение (билборд, OOH) | Krea Max (до 22K фото / 8K видео) |
| Нулевой бюджет + GPU | Upscayl (open-source, локально) |
| Встроить в batch-конвейер | дешёвый API (Clipdrop / Let's Enhance) |

⚠ Ключевые сравнения — из одного независимого теста (AI Magicx, 100 изображений), методология single-source. ⚠ Ребрендинг Freepik→Magnific (апрель 2026) сломал старые API-эндпоинты — при прямой интеграции перепроверить.

### Outpaint/reframe вместо повторной генерации под формат
- **Inpainting** чинит контент **внутри** границ кадра (убрать объект, сменить цвет продукта, водяной знак). **Outpainting** генерирует **за** пределами кадра (4:3→16:9, портрет под баннер).
- Расширение форматов карусели/видео (9:16 → 1:1 → 4:5): **outpaint** уже сгенерированного кадра вместо нового дорогого запуска. Правило **25–30% за проход**, не один большой скачок.
- Главный риск — **style bleed** (рассинхрон освещения на стыке): маска + захват 5–20 px в оригинал, промпт с направлением света и Kelvin, сила генерации 0.6–0.8. Ручная проверка: логотип/текст, тени/отражения, лица/руки не «плывут», края не «оплавлены».

### Правка клипа целиком вместо перегенерации (Kling O1 Edit)
Флоу `/video-edit` (вход 3-10 с, вывод 720p): relight / object-swap / reframe / recolor **по всему клипу** вместо повторной дорогой генерации. Брать, когда финал почти готов и нужна точечная замена. ⚠ отдельного video-`id` в MCP-дампе 2026-07-11 нет — проверить доступ в MCP/UI.

### Пост-обработка стыков (обязательна при склейке разных моделей)
- **`video_deflicker`** — убирает мерцание на стыках AI-генераций/между моделями (риск из M03). Прогонять при монтаже клипов из разных моделей.
- **`sam_3_video` / `video_background_remover`** — вырезание фона у видео (композитинг, замена фона).
- Апскейл видео: `topaz_video` / `bytedance_video_upscale` (до 4k/2160p), `video_upscale`.

## Motion-группировка (M08)

**Common fate** — самый мощный принцип гештальт-группировки для видео/motion: элементы, движущиеся **синхронно**, воспринимаются как единый объект даже поверх идеального статического камуфляжа (расширение: синхронное изменение яркости группирует так же сильно, как синхронное движение).

**Практика для движка:**
- Связанные элементы (**текст + подложка**) двигаются **одним таймингом** → читаются как группа. Не анимировать текст и фон отдельными таймингами (это разрушает common fate).
- **Один визуальный акцент в движении** (Von Restorff): не пять конкурирующих анимированных акцентов на кадре — иначе эффект переходит в медленный последовательный поиск, теряется.

## Виральность видео (M07)

### K-фактор-мышление (KPI, не сворачивать в общий «engagement»)
- **saves/reach** и **shares/reach** — отдельные ключевые метрики. Save = «вернусь позже» (сильнейший сигнал намерения), Share = публичный эндорсмент, DM = высокое доверие, Comment = «ответил».
- **Social K-factor** для контент-цикла = доля поделившихся × среднее число получателей на share. Цель — растить K к 1+ в рамках Learning Loop.

### Персоны шерящих (NYT «Psychology of Sharing»)
Для **B2B/edtech-аудитории IKIGAI PROMOTION** приоритетны:
- **Careerists** — репост ради проф. репутации.
- **Altruists** — репост чтобы помочь другим.

Логичнее, чем ставка на Boomerangs (репост ради реакции/валидации). CTA-форматы под разные персоны. ⚠ Привязка персон к B2B/edtech — гипотеза, требует проверки на реальных охватах.

### «Слот под пересылку» в финале
Финал ролика проектировать не как призыв в подписи, а как **встроенный в визуал элемент под пересылку** («отправь тому, кто…» — с местом называния адресата). Опирается на STEPPS (Berger): arousal (awe/гнев/восторг, **не** спокойная грусть) — главный двигатель шеринга; Practical Value → save-worthy форматы (чек-лист/фреймворк/сравнение).

## Performance-видео workflow (M12)

Performance-креатив жёстче органики: первый кадр под **холодный** трафик без контекста подписки, решение «смотреть/пролистать» за **~1.2 сек**. Лучшие органические Reels часто переигрывают специально снятый рекламный креатив.

### Последовательность AI-UGC → real-creator (стадии, не конкуренция)
1. **Дешёвая AI-валидация 20–30 хуков** (≈ ноль за вариант; видео-стек Higgsfield/Kling/Veo/Hailuo).
2. **Отбор 3–5 углов**, попадающих в целевой CPA.
3. **Масштабирование победителя реальным креатором** ($150–500/видео).
4. Постоянное обновление снова через AI-UGC.

Структура UGC-ролика: Hook (0–3с) → Проблема/напряжение (3–8с) → Продукт/решение (8–18с) → Пруф (18–25с) → CTA (25–30с).

### Метрики (для будущего learning loop движка)
- **Hook Rate** — 3-сек просмотры / показы («остановил скролл»).
- **Hold Rate** — ThruPlay / 3-сек просмотры («удержал внимание»).
- **Thumbstop Rate** — тот же принцип, что Hook Rate.
- Лучший Hook и лучший Hold — **не всегда один ролик**; фиксировать характеристики каждого отдельно.
- ⚠ «Thumbstop 55% vs 5–10%», «CAC –30%», «покупательское намерение –16% при 6+ показах» — из кейсов отдельных практиков, не системное исследование (single-source; верифицировать).

### «Одна переменная на батч» (Entity ID дисциплина)
Meta группирует креативы в **Entity ID** по смыслу (кадр, цвет, кто говорит, тема, тон аудио), не по файлу. 8 «разных» но структурно одинаковых креативов схлопываются в один Entity ID и **конкурируют друг с другом** за один аукционный слот (CPM растёт, охват — нет).
- [ ] Соседние креативы батча отличаются **минимум по 2 из 3 осей**: сообщение / визуальная подача / формат.
- [ ] Прописан **один тестируемый параметр** на батч (hook-категория / angle / стиль пруфа / тон / персона), остальные зафиксированы.
- [ ] Бриф написан как **гипотеза**, а не творческое направление.
- Тестировать 20–30 подлинно разных Entity ID, не 50 перекрашенных версий.

### Сроки усталости креатива (когда обновлять)
TikTok ~72 часа до –50% эффективности · Meta холодный трафик 10–14 дней · Meta ретаргетинг 2–3 недели · Reels как TikTok (еженедельно) · YouTube Shorts 3–4 недели.
